# LexRead 法学智能阅读助手

LexRead 是一个面向法学研究者的桌面端研究工作台。本实现以“原文可溯源、推理可校正、成果可复用”为核心，覆盖论文与裁判文书的单篇阅读闭环。

## 当前能力

- 项目首页：新建研究项目或选择已有项目；项目是论文、裁判文书、卡片与成果的一级容器。
- 上传与解析：真实 PDF 本地上传、原生文字层提取、异常字形检测、Kimi Vision OCR、书签/目录校对和可恢复任务状态。
- 研究项目：集中上传论文与裁判文书，并查看项目文档、研究问题、卡片和总体进度。
- 论文概览：先查看核心问题、作者结论、适用边界、论证图谱与要点，再进入原文。
- 论文阅读器：逐节点核验 AI 判断，可直接跳到真实 PDF 页面和原文锚点。
- 裁判阅读器：区分当事人主张、法院事实、证据、规范和要件判断。
- 项目资料库：观点卡、案例卡、规范卡与引用卡严格归属各自项目，可回到原文，不跨项目混用。
- 两层项目空间：进入项目后只保留“项目概览”和“项目资料库”；文档、进度、研究问题与所有研究卡片都围绕当前项目组织。
- 裁判分析：全文分段提取当事人主张、法院认定事实、证据、法律、说理和结论，再综合为可逐节点核验的裁判推理路线。

阅读交互状态保存在浏览器本地存储中；上传的原文件、解析页、文本块、目录修改、分析任务和结果保存在本机 `data/` 目录中。该目录和本地密钥文件均已排除在 Git 之外。

## Kimi 配置

复制 `.env.local.example` 为 `.env.local`，只在本机填写密钥：

```bash
KIMI_API_KEY=在这里粘贴新密钥
KIMI_MODEL=kimi-k2.6
KIMI_OCR_MODEL=moonshot-v1-8k-vision-preview
KIMI_BASE_URL=https://api.moonshot.cn/v1
```

密钥只由本机 API 读取，不会进入前端构建、浏览器存储或 Git。由于聊天记录不是秘密管理器，若密钥曾粘贴到聊天中，建议先在 Kimi 控制台轮换。

也可以点击网页顶栏的“Kimi API”入口完成设置和连接测试。网页设置保存在本机 `data/local-settings.json`，手工 `.env.local` 配置仍然兼容；两种方式都不会把密钥回显到浏览器。

## 本地运行

macOS 用户可以直接双击项目根目录中的 `LexRead 一键启动.command`。启动器会自动检查依赖、复用已运行的服务或选择可用端口，并打开浏览器。关闭启动器终端窗口即可停止本次启动的服务。

也可以在终端中手动运行：

```bash
npm install
npm run dev
```

生产构建与检查：

```bash
npm run typecheck
npm run check:judgment
npm run build
```

## 结构说明

- `server/`：本地 API、PDF 解析、Kimi 结构化分析与原子化 JSON 持久化。
- `src/api.ts`：前端与本地 API 之间的类型安全边界。
- `src/store.tsx`：项目、文档、阅读节点和研究卡片的共享状态与业务动作。
- `src/data.ts`：贯穿全站的演示研究数据。
- `src/pages/`：七个核心业务页面。
- `src/components/`：应用框架、导航与通用交互组件。
- `src/styles.css`：设计系统、三栏工作区与响应式规则。

当前纵向切片已打通“项目 → 上传 → PDF 文字层解析 → 低置信页 Kimi Vision OCR → 论文/裁判专用全文分析 → 单篇概览或裁判推理路线 → 原文锚定核验 → 本项目资料库/成果”。长文不再截断前 18 万字符，而是按目录和页块完整覆盖后再综合。本机只负责将指定页面渲染为临时 JPEG；点击 OCR 后仅低置信页面图片会发送至 Kimi，不会上传整本原 PDF。每页 OCR 的模型、用量、置信度、坐标和警告都会持久化。账户、多用户权限和云端部署仍属于后续阶段。
